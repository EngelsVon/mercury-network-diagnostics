# Plan 04-01: Passive context and bounded TCP discovery

## Task 1: Canonical passive topology evidence

Create platform-neutral records/parsers for connected IPv4 prefixes, passive
neighbor cache entries, Wi-Fi AP and direct LLDP evidence. Keep source and
capability data. Emit the existing no-switch-observable limitation whenever no
direct LLDP record exists.

Verification: fixture tests cover valid records, absent tools, permissions,
invalid input, no IPv6 enumeration, and no switch inference from routes or
neighbors.

## Task 2: Immutable authorized discovery service

Implement a request with fixed common/custom/full port profiles. Compile each
selected IPv4 address/port through the canonical scope/budget planner and run
TCP connects via TaskContext. Require authorization; require separate full-mode
confirmation; preserve connect/refusal/timeout/permission/error distinctions.

Verification: controlled loopback server/refusal/timeout tests, authorization
and scope rejection before I/O, cancellation/progress/budget tests.

## Task 3: Facade and projections

Expose passive and active discovery only through MercuryApplication and CLI
commands. JSON remains the canonical TaskResult wire representation; human
projection cites evidence and states topology limitations.

Verification: parser rejects arbitrary payload/protocol knobs and CLI/API
outputs project the same result.
