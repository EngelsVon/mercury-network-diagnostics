<objective>
Add optional fixed-profile native Nmap observations and expose the completed
internal mapping/paired coverage service through the shared CLI and WebUI.

Purpose: operators need a convenient internal assessment surface and optional
native TCP/UDP/SCTP evidence without converting Mercury into an arbitrary
subprocess launcher, browser-side scanner, or peer-controlled relay.

Output: policy-derived Nmap adapter, typed native evidence, accessible CLI/Web
requests and results, and regression protection for peer/history trust boundaries.
</objective>

<threat_model>
Assets: private-only destination boundary, host/network availability, peer mTLS
trust, Web listener credentials, evidence/history integrity and operator safety.

Threats and mitigations:

- Free-form Nmap arguments bypass scope and budgets.  Derive a fixed argv only
  from a revalidated ProbePlan; prohibit target files, scripts, proxy/decoy,
  input sources and arbitrary options.
- Nmap XML lies outside expected size/schema.  Request XML only to a bounded
  temporary location, parse with `xml.etree.ElementTree` under explicit byte/
  element ceilings, reject malformed/unknown critical fields and remove only the
  exact temporary file after it is closed.
- UI parameters bypass app policy.  Parse request DTOs only, then call one
  MercuryApplication service method; no JavaScript opens a scan socket or starts
  Nmap.
- A non-loopback listener or peer loses authentication.  Preserve TLS/token/
  CSRF/origin controls for Web and mTLS/token/pin/replay/source controls for
  peer control; test rejection paths after UI changes.
- Output/history leaks certificates, correlation material or tokens.  Continue
  redaction/secret validation and store source/provenance rather than commands,
  raw tags or secrets.
</threat_model>
