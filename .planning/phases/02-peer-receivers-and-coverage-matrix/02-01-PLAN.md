<objective>
Replace the single fixed paired TCP/UDP lease with a closed, correlated receiver
matrix that lets two configured Mercury peers test the finite carriers defined in
`.planning/TUNNEL-COVERAGE.md` in both directions.

Purpose: an administrator needs direct, receiver-side evidence that a selected
carrier crossed an isolation boundary.  The receiver must never become a generic
packet relay, arbitrary listener, or third-party scan service.

Output: versioned coverage evidence, profile-specific leases/receivers, a
bidirectional coverage result, and a matrix that names both positive carriers
and every coverage gap.
</objective>

<threat_model>
Assets: the peer-control trust boundary, the two peer hosts, internal ACLs,
evidence integrity, and bounded local resources.

Entry points: peer `capabilities`, `submit`, `read-result`, `cancel`; configured
receiver ports/certificates; data-plane listeners; native ICMP/neighbour helpers;
and serialized result/report output.

Threats and mitigations:

- A caller chooses an arbitrary protocol, destination, bind address, port, or
  payload.  Admit only named profiles, preconfigured profile/port bindings,
  fixed tag shapes and fixed reply bytes derived from an immutable local plan.
- A peer supplies a forged receipt.  Bind each receipt to the authenticated peer,
  one-time correlation, source tuple, digest/length, short lease, and local send
  evidence; preserve both evidence records instead of flattening them.
- A listener or pending result survives its lease.  Use `finally` cleanup,
  bounded in-memory result retention and cancellation tests.
- ICMP/raw observation needs privilege and ARP/ND is misread as remote reachability.
  Report capability/permission gaps and mark ARP/ND not applicable for a
  cross-subnet pair; never infer a remote L2 response from a gateway neighbour.
- TLS test receivers weaken control-plane mTLS.  Keep the existing peer-control
  certificate/token/pin controls separate from a deliberately configured data
  receiver certificate and never expose key material in observations/history.
</threat_model>
