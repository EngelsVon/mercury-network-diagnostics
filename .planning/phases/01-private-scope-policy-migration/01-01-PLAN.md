<objective>
Make private-network admission an invariant of every active Mercury path before any packet sender, peer receiver, or Nmap adapter is introduced.

Purpose: Phase 2 needs a single trusted definition of an internal endpoint. The policy implementation must reject public and documentation destinations before any active I/O while preserving the existing typed evidence, peer trust controls, task planning, and CLI/Web service boundary.

Output: canonical allowlist enforcement, public-profile migration, regression tests, and matching documentation.
</objective>

<threat_model>
Assets: internal-network boundary, endpoint availability, peer control, operator task history, and future coverage-assessment trust.

Entry points: literal/CIDR target parsing, hostname resolution/recheck, ScopeGrant construction, diagnosis profile selection, discovery, trace, CLI plan, Web task broker, peer configuration, and a future Nmap subprocess.

Threats:

- A public literal, CIDR, or documentation range reaches a socket/native command through one missed entry point.
- A hostname resolves to a public address after initial admission.
- A retained public profile bypasses the new allowlist.
- A private-only change weakens mTLS, token, certificate pinning, plan validation, cancellation, or result evidence.

Mitigations:

- One explicit address/CIDR allowlist in the canonical policy module, exercised by ScopeGrant and every resolved literal.
- Resolver snapshot and socket-boundary recheck tests for public/escaping answers.
- No presenter-specific validators or special profile bypasses.
- Regression tests for peer trust and existing immutable plan/task paths.

Residual risk:

- A hostname can change between tests and real execution; the existing recheck remains the mitigation.
- Native platform tools may expose incomplete capability data; the phase must fail closed before invoking one with an invalid target.
</threat_model>
