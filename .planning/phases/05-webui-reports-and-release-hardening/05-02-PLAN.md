# Plan 05-02: History comparison and safe reports

## Task 1: Central redaction and report generation

Implement deterministic redaction over canonical result wire data, JSON export
and a self-contained escaped HTML report. Token/secret material must always be
rejected/redacted; hostnames, MACs, public IPs and raw payload values are
redacted by default and may only be retained through an explicit safe option.

Verification: fixture tests cover nested sensitive data, public/private
addresses, host/MAC fields, HTML escaping and report determinism.

## Task 2: History facade and compatible comparison

Add facade functions that load completed history, compare only compatible task
schema/type results, and produce cited changed/unchanged/missing evidence
without treating absence as failure.

Verification: SQLite-backed tests cover history list/show, compatible delta,
incompatible rejection and no direct persistence access from Web presentation.

## Task 3: CLI/Web projections

Add closed CLI history compare/export commands and corresponding authenticated
Web API routes. Both project the same report/comparison service result.

Verification: JSON identity and human/HTML output tests, plus Web authorization
and default-redaction regression coverage.
