<interfaces>
Define frozen validated PeerConfig and PeerFrame values in peer.py. PeerConfig
contains identity, bind host/control port, certificate/key/CA/token paths,
configured certificate pins, fixed peer addresses, and unsafe-development.
PeerFrame contains version, operation, correlation ID, peer identity,
issued/expiry timestamps, nonce, and a strict operation body.

PeerAgent dispatches only capabilities, submit, read-result, and cancel.
Handlers are injected and closed: no frame field may carry a destination, CIDR,
arbitrary port, hostname result, payload, scope, or runner. PeerClient uses the
same strict encoder/decoder. MercuryApplication is the only facade allowed to
start or stop an agent; CLI additions wait for Plan 03.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator files to peer config | Certificate/key/token paths and fixed peer identity become live authentication material. |
| Remote TLS stream to dispatcher | A remote peer can deliver malformed, replayed, oversized, or credential-bearing input. |
| Peer control to handlers | A control frame must not become remote probe, result, or cancellation authority. |
| Audit/history/output | Authentication paths could disclose sensitive material. |
